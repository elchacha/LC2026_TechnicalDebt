Diagnostic SOQL — 3 Essential Queries

Visualforce pages — last access date ⚠ Prod org only

Identify which VF pages are actually used — candidates for cleanup.

SELECT ApexPageId, ApexPage.Name, MAX(MetricsDate) MetricsDate
FROM VisualforceAccessMetrics
GROUP BY ApexPage.Name, ApexPageId

Orphan layouts — not assigned to any active profile Tooling API

Layouts no active user profile references — safe to decommission.

SELECT Id, Name, TableEnumOrId FROM Layout
WHERE layoutType = 'Standard'
  AND Id NOT IN (SELECT LayoutId FROM ProfileLayout
    WHERE ProfileId IN ('Id1','Id2','Id3')
    AND (recordType.IsActive = true OR recordTypeId = ''))
ORDER BY EntityDefinitionId

Component dependencies — before any deletion Tooling API

Check what depends on a component before removing it — avoids cascading errors.

SELECT RefMetadataComponentId, RefMetadataComponentName,
       RefMetadataComponentType
FROM MetadataComponentDependency
WHERE MetadataComponentId IN ('Id1','Id2')

Overlapping automations that nobody dares to touch.
When you see it
How to address it
A record update triggers the same email twice
→
Audit with Salesforce Optimizer + Flow list view — map all automations per object
A Flow fails with CANNOT_INSERT_UPDATE_ACTIVATE_ENTITY — recursive trigger
→
Enforce one entry-point Flow per object per trigger context (before / after save)
Disabling one Process Builder breaks something completely unrelated
→
Retire Process Builders and Workflow Rules — migrate into record-triggered Flows
Nobody knows which automation runs first
→
Document execution order inline in Flow descriptions

🏗️Architecture Debt
Design decisions that were made without a target architecture — and now constrain the whole Salesforce ecosystem.
When you see it
How to address it
Multiple systems update the same Salesforce record with no clear system of record
→
Define explicit system-of-record ownership per domain
Integrations are point-to-point instead of going through a controlled integration layer
→
Introduce standardized API-first or event-driven integration patterns
A small change in Salesforce unexpectedly breaks another system
→
Reduce coupling and document dependencies between systems
The same capability is rebuilt several times by different teams
→
Create reusable reference architectures and shared components

📊Data Model Debt
Fields and picklists that have outlived their usefulness — and nobody knows which ones.
When you see it
How to address it
Picklist reports show 15 variations of what should be 3 values
→
Standardize picklist values — define a canonical list, use Global Value Sets
Page layouts so crowded that users scroll past the fields they need
→
Use Field-Level Security to hide irrelevant fields rather than delete immediately
Nobody can safely delete a field without a full dependency check
→
Field Usage Analytics (Setup): fields with zero population are safe candidates
Dashboards vary wildly depending on which status field you use
→
Establish a "create field" process: description, owner, and review required

💻Apex Code Debt
Code that works today but will break tomorrow — and has no safety net.
When you see it
How to address it
A deployment fails because unrelated tests suddenly break
→
Write meaningful tests: assert specific field values and error conditions
A new requirement means rewriting the trigger from scratch
→
Adopt the Trigger Handler pattern (fflib, Kevin O'Hara): one trigger per object
A nightly batch fails in production after a data import
→
Bulkify everything: SOQL and DML always outside loops — use collections and maps
Nobody wants to modify the trigger — "it's too risky"
→
Introduce a service layer to isolate business logic from trigger context
Key concepts
Trigger Handler patternbulkificationgovernor limitstest coveragefflibApex Enterprise Patterns
🔗Integration Debt
External systems connected by fragile assumptions rather than solid contracts.
When you see it
How to address it
A sandbox refresh breaks several integrations immediately
→
Never hardcode Record IDs — use External IDs, Named Credentials, or Custom Metadata
An API version deprecation notice triggers emergency work across multiple teams
→
Pin to a recent, stable API version — establish a yearly review process
Failed syncs are discovered by end users, not by monitoring
→
Log failures to a custom object, alert via Platform Events or email
Credentials stored as plaintext in custom fields or Apex constants
→
Use Named Credentials for all authentication — no credentials in code
+
Document every integration: source, target, trigger, frequency, owner
Key concepts
Named CredentialsExternal IDAPI versioningPlatform Eventsretry logicoutbound messaging
📋Governance Debt
An org where anyone can change anything, anytime, in any way they like.
When you see it
How to address it
Onboarding a new developer takes weeks just to understand the naming conventions
→
Define and enforce naming conventions for all metadata — document in a living wiki
Two teams create near-identical custom fields because neither knew the other existed
→
Make descriptions mandatory: no deployment without a description on every new element
A Flow is modified in production "just to test something quickly" — and breaks downstream
→
Introduce a deployment pipeline: Sandbox → UAT → Production with change tracking
Setup audit trail shows dozens of unexplained changes per day from multiple admins
→
Use a CHANGELOG or Jira — every org change traceable to a request and a person

🔐Security Debt
The most dangerous type — because nothing breaks until it's too late.
When you see it
How to address it
Standard users can see or edit records they have no business reason to access
→
Audit profiles and permission sets — use Strongpoint or Own Security scanner
A Connected App from a vendor the company no longer works with is still active
→
Review Connected Apps quarterly — revoke any app unused for 90+ days
A data leak can't be traced — audit trail history has already rolled over (180-day limit)
→
Export Setup Audit Trail regularly — before the 180-day window rolls over
Sensitive fields (salary, SSN, contract value) are visible to all profiles
→
Restrict OAuth scopes — no app should request full API access unless required
+
Apply least privilege: start from zero access, grant only what is explicitly needed
